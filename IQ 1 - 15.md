# C# Interview Questions and Answers — Complete Preparation Notes

## 1. What is C#? What are its key features?

>1. C# is a modern, general-purpose, object-oriented programming language developed by Microsoft.
>2. It is commonly used to build web applications, desktop applications, APIs, games, and enterprise software using .NET.

Key features:

1. Object-oriented: Supports encapsulation, abstraction, inheritance, and polymorphism to organize code into reusable classes and objects.
    
2. Type-safe: Helps prevent invalid operations on data types and catches many type errors at compile time.
    
3. Automatic memory management: The .NET garbage collector reclaims memory 
   occupied by objects that are no longer reachable.
    
4. Rich libraries: Provides built-in classes for working with files, collections, strings, databases, networking, and more.
    
5. Cross-platform: Modern .NET applications can run on Windows, Linux, and macOS, depending on the application and its dependencies.
    
6. Asynchronous programming: Supports `async` and `await` for writing readable asynchronous code.
    

Example:

```
using System;

class Program
{
    static void Main()
    {
        Console.WriteLine("Hello, C#!");
    }
}
```

## 2. Difference between .NET Framework, .NET Core, and .NET 5+

Interview answer: .NET Framework is Microsoft's original Windows-focused development platform. .NET Core was introduced as a modern, open-source, cross-platform alternative. Starting with .NET 5, Microsoft unified the platform under the name .NET.

|Feature|.NET Framework|.NET Core|.NET 5+|
|---|---|---|---|
|Platform|Windows-focused|Cross-platform|Cross-platform|
|Status|Legacy; maintenance and security updates continue|Historical product line; succeeded by .NET 5|Current unified product line|
|Open source|Some components|Yes|Yes|
|Performance|Depends on application|Designed for modern, high-performance apps|Continues performance improvements|
|Typical use|Existing Windows applications, older ASP.NET apps|Modern applications built before .NET 5|New APIs, web apps, cloud services, desktop apps|
|Version examples|4.8.1|3.1|.NET 6, 8, 10|

Key points:

1. .NET Framework is mainly used to maintain existing Windows applications.
    
2. .NET Core introduced cross-platform support and a modular design.
    
3. .NET 5 was the successor to .NET Core 3.1; Microsoft dropped the word “Core” from the main product name.
    
4. Modern .NET supports technologies such as ASP.NET Core, cloud services, and cross-platform development.
    
5. For new projects, developers generally choose a supported modern .NET release rather than starting with .NET Framework, unless they need a Framework-specific technology.
    

## 3. What is the CLR and what does it do?

Interview answer: CLR stands for Common Language Runtime. It is the execution environment of .NET that runs managed code and provides services such as memory management, exception handling, and type safety.

Key points:

1. Executes managed code: The CLR works with compiled .NET Intermediate Language (IL), using a JIT compiler to translate IL into native machine code when needed.
    
2. Memory management: Coordinates garbage collection to reclaim memory from unreachable managed objects.
    
3. Exception handling: Provides a consistent mechanism for handling runtime exceptions.
    
4. Type safety: Enforces runtime type rules for managed code.
    
5. Security and reliability: Provides runtime checks and services that help managed applications execute safely and consistently.

## 4. What are the four pillars of OOP?

Interview answer: The four pillars of object-oriented programming are encapsulation, abstraction, inheritance, and polymorphism. They help developers create organized, reusable, maintainable, and flexible software.

1. Encapsulation: Combines data and related behavior in a class and controls access to the object's state.
    
    Example: Making a bank account balance private and allowing changes through deposit and withdrawal methods.
    
2. Abstraction: Hides unnecessary implementation details and exposes only the operations a user needs.
    
    Example: A driver uses a car's steering wheel without needing to understand the internal steering mechanism.
    
3. Inheritance: Allows a derived class to reuse accessible members and behavior from a base class.
    
    Example: `Dog` inherits common behavior from `Animal`.
    
4. Polymorphism: Allows the same operation or method call to behave differently depending on the context or actual object.
    
    Example: `Dog` and `Cat` can each implement their own `MakeSound()` method.
    

Remember: Encapsulation protects state, abstraction hides complexity, inheritance promotes reuse, and polymorphism provides flexibility.

## 5. Value type vs reference type

> 1. Value types store their values directly within the variable 
> 2. while reference-type variables store a reference to an object. This difference affects assignment, copying, and how objects are shared.

| Feature    | Value type                                                 | Reference type                                      |
| ---------- | ---------------------------------------------------------- | --------------------------------------------------- |
| Examples   | `int`, `bool`, `char`, `struct`, `enum`                    | `string`, arrays, classes, delegates                |
| Assignment | Copies the value                                           | Copies the reference                                |
| Sharing    | Copies are independent values                              | References may point to the same object             |
| Null       | Not `null` by default; nullable value types are possible   | Can be `null`                                       |
| Memory     | May be stored inline or on the stack, depending on context | Objects are generally allocated on the managed heap |

Example:

```
int a = 10;
int b = a;
b = 20;
// a is still 10

Student s1 = new Student();
Student s2 = s1;
// Both references point to the same object
```

Key points:

1. Value types include numeric types, `bool`, `char`, structures, and enumerations.
    
2. Reference types include classes, arrays, strings, and delegates.
    
3. Assigning a value type copies its value.
    
4. Assigning a reference type copies the reference, not the entire object.
    
5. Do not assume that all value types live on the stack; their storage depends on where they are used.
    

## 6. Class vs struct

Interview answer: A class is a reference type generally used to represent objects with identity and behavior. A struct is a value type generally used for small data structures whose values can be copied independently.

|Feature|Class|Struct|
|---|---|---|
|Type category|Reference type|Value type|
|Assignment|Copies reference|Copies value|
|Inheritance|Can inherit from one class|Cannot inherit from another class or struct|
|Null|Can be `null`|Not `null` by default|
|Typical use|Complex objects and entities|Small values such as coordinates or measurements|

Key points:

1. A class is declared using `class`, while a struct is declared using `struct`.
    
2. Multiple variables can refer to the same class object.
    
3. Assigning a struct normally copies its field values.
    
4. A class can be used as a base class; a struct cannot be a base class.
    
5. Use a struct for small value-like data when appropriate, and a class for objects with identity, shared state, or more complex behavior.
    

Example:

```
class Student
{
    public string Name = "";
}

struct Point
{
    public int X;
    public int Y;
}
```

## 7. Abstract class vs interface

Interview answer: An abstract class provides a common base for related classes and can contain implemented methods and shared state. An interface defines a contract that a class or struct agrees to implement.

|Feature|Abstract class|Interface|
|---|---|---|
|Purpose|Share common implementation and behavior|Define a capability or contract|
|Methods|Can have abstract and implemented methods|Can declare members and, in modern C#, some members with default implementations|
|Fields and state|Can have instance fields|Cannot declare ordinary instance fields|
|Inheritance|A class can inherit only one class|A type can implement multiple interfaces|
|Constructors|Can have constructors|Cannot have instance constructors|

Key points:

1. An abstract class cannot be instantiated directly.
    
2. A derived concrete class must implement inherited abstract members.
    
3. A class implements an interface using `:`.
    
4. A class can inherit one base class while implementing multiple interfaces.
    
5. Choose an abstract class when related types need shared code or state; choose an interface when different types should follow the same contract.
    

Example:

```
interface IPrintable
{
    void Print();
}

abstract class Animal
{
    public abstract void MakeSound();
}

class Dog : Animal, IPrintable
{
    public override void MakeSound() => Console.WriteLine("Bark");
    public void Print() => Console.WriteLine("Dog");
}
```

## 8. What is polymorphism? Compile-time vs runtime?

Interview answer: Polymorphism means “many forms.” In C#, it allows the same method name or interface to produce different behavior depending on the parameters or the actual object.

|Feature|Compile-time polymorphism|Runtime polymorphism|
|---|---|---|
|Common technique|Method overloading|Method overriding|
|Decision|Made by the compiler|Made at runtime for virtual dispatch|
|Parameters|Overloads have different parameter lists|Overridden methods have compatible signatures|
|Keywords|No special keyword is required for overloading|Commonly `virtual` and `override`|
|Benefit|Offers convenient methods for different inputs|Allows derived classes to provide specialized behavior|

Key points:

1. Compile-time polymorphism is commonly achieved through method overloading.
    
2. Runtime polymorphism is commonly achieved through method overriding.
    
3. Overloading lets one method name support different parameter lists.
    
4. Overriding lets a derived class replace an inherited virtual method implementation.
    
5. Runtime polymorphism supports flexible code that works with a base class or interface.
    

Example:

```
class Animal
{
    public virtual void Sound() => Console.WriteLine("Animal sound");
}

class Dog : Animal
{
    public override void Sound() => Console.WriteLine("Bark");
}

Animal animal = new Dog();
animal.Sound(); // Bark
```

## 9. What are the access modifiers in C#?

Interview answer: Access modifiers define where a class, method, property, or other member can be accessed from. They help control visibility and support encapsulation.

|Modifier|Meaning|
|---|---|
|`public`|Accessible wherever the containing type is accessible|
|`private`|Accessible only within the containing type|
|`protected`|Accessible within the containing type and its derived types|
|`internal`|Accessible within the same assembly|
|`protected internal`|Accessible within the same assembly or from derived types in another assembly|
|`private protected`|Accessible within the containing type and derived types in the same assembly|

Key points:

1. `public` provides the broadest normal member accessibility.
    
2. `private` restricts access to the containing type.
    
3. `protected` is useful when derived classes need access to a member.
    
4. `internal` is useful for code that should remain inside one assembly.
    
5. `protected internal` and `private protected` combine inheritance and assembly boundaries in different ways.
    

Example:

```
class Employee
{
    public string Name = "";
    private double salary;
    protected int employeeId;
}
```

## 10. What is inheritance? Does C# support multiple inheritance?

Interview answer: Inheritance is an OOP feature that allows a derived class to reuse accessible members and behavior from a base class. C# supports single class inheritance but does not allow a class to inherit from multiple classes.

Key points:

1. The base class contains common behavior.
    
2. The derived class inherits accessible members and can add its own behavior.
    
3. Inheritance reduces code duplication when types have a genuine “is-a” relationship.
    
4. C# supports single, multilevel, and hierarchical class inheritance.
    
5. C# does not support multiple inheritance of classes, but a class can implement multiple interfaces.
    

Example:

```
class Animal
{
    public void Eat() => Console.WriteLine("Eating");
}

class Dog : Animal
{
    public void Bark() => Console.WriteLine("Barking");
}

Dog dog = new Dog();
dog.Eat();
dog.Bark();
```

## 11. String vs StringBuilder

Interview answer: `string` is an immutable reference type, so an operation that changes its text produces a new string. `StringBuilder` is a mutable class designed to make repeated text modifications more efficient.

|Feature|`string`|`StringBuilder`|
|---|---|---|
|Mutability|Immutable|Mutable|
|Namespace|`System`|`System.Text`|
|Modification|Produces a new string value|Modifies the builder's contents|
|Common operations|`Replace()`, `Substring()`, `ToUpper()`|`Append()`, `Insert()`, `Replace()`, `Remove()`|
|Best use|Ordinary text and few modifications|Many repeated modifications, especially in loops|

Key points:

1. A string cannot be changed in place.
    
2. Repeated concatenation may create many temporary string objects.
    
3. `StringBuilder` can reuse its internal buffer when its capacity allows.
    
4. `StringBuilder` is often more efficient for repeated modifications, though the best choice depends on the workload.
    
5. Call `ToString()` to obtain a normal string from a `StringBuilder`.
    

Example:

```
using System.Text;

string text = "Hello";
text += " World";

StringBuilder sb = new StringBuilder("Hello");
sb.Append(" World");

string result = sb.ToString();
```

## 12. Why is string immutable?

Interview answer: Strings in C# are immutable because their contents cannot be changed after the string object is created. Operations that appear to modify a string return a new string instead.

Key points:

1. Predictability: A string's contents remain stable after creation.
    
2. Safe sharing: Multiple variables can reference the same string without one variable changing its contents for the others.
    
3. Threading benefits: Immutable contents reduce the risk of conflicting modifications to the same string object.
    
4. String interning: Identical string literals may share a stored string instance safely because its contents cannot be modified.
    
5. Trade-off: Repeated modifications can create extra allocations, which is why `StringBuilder` is useful for some workloads.
    

Example:

```
string name = "Hello";
name.Replace("H", "Y");

Console.WriteLine(name); // Hello

name = name.Replace("H", "Y");
Console.WriteLine(name); // Yello
```

The first call returns a new string, but the result is discarded. The second call assigns the returned string to `name`.

## 13. `ref` vs `out`

Interview answer: Both `ref` and `out` allow a method to work with a variable passed by reference. With `ref`, the variable must already be initialized; with `out`, the method must assign a value before it returns normally.

|Feature|`ref`|`out`|
|---|---|---|
|Before method call|Variable must be initialized|Variable need not be initialized|
|Method requirement|Can read and modify its existing value|Must assign it before returning normally|
|Purpose|Read and update an existing variable|Return additional result values|
|Call syntax|Uses `ref`|Uses `out`|

Key points:

1. Both keywords must appear in the method declaration and the call.
    
2. `ref` allows the method to use the original value.
    
3. `out` is useful when a method needs to produce an additional result.
    
4. Both refer to the caller's variable, rather than simply receiving a copy.
    
5. `TryParse()` is a common example of an `out` parameter.
    

Example:

```
static void Update(ref int x)
{
    x = x + 10;
}

static void GetValue(out int x)
{
    x = 100;
}

int a = 5;
Update(ref a);        // a becomes 15

GetValue(out a);      // a becomes 100
```

## 14. What are boxing and unboxing?

Interview answer: Boxing converts a value type into an `object` or compatible interface reference. Unboxing extracts a value type from a boxed object.

Key points:

1. Boxing wraps a value type value in an object.
    
2. Unboxing requires an explicit cast to the correct value type.
    
3. Boxing can allocate an object and add runtime overhead.
    
4. Unboxing requires the boxed value to have a compatible underlying type.
    
5. Generic collections such as `List<int>` avoid the boxing commonly associated with storing integers in a non-generic `ArrayList`.
    

Example:

```
int number = 10;

object obj = number;  // Boxing
int result = (int)obj; // Unboxing
```

A wrong unboxing cast, such as casting a boxed `int` directly to `long`, throws `InvalidCastException`. Convert the value after unboxing if a different numeric type is required.
