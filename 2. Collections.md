# What are Collections?

>1. Collections in C# are used to store and manage multiple items together. 
>2. They provide methods to add, remove, search, and access data efficiently.
>3. Common collections include `List`, `Dictionary`, `Queue`, `Stack`, and `HashSet`

### Generic vs Non Generic

In C#, collections are divided into generic and non-generic collections. Generic collections store a specific data type and provide type safety, whereas non-generic collections can store different types of objects in the same collection. Generic collections are generally preferred because they reduce type-casting and avoid many runtime type errors



## Generic Collections

> 1. Generic collections allow us to store multiple values in a single collection.
>2. We specify the data type using a type parameter, such as `<int>` or `<string>`.
 >3. They ensure that only compatible values can be added to the collection.
 >4. They are generally preferred over non-generic collections because they provide better type safety and are easier to work with.
 
## Non Generic Collections

> 1. Non-generic collections can store different types of values, such as integers, strings, and decimal numbers, in the same collection.
  >2. They do not use a generic type parameter such as `<T>` to specify the element type.
>3. Since elements are handled as `object`, retrieving a value as a specific type may require explicit casting.
>4. They are less type-safe than generic collections because incompatible values can be added without a compile-time type error.
>5. They are mainly encountered in older .NET code; generic collections are generally preferred in modern C#.

## Differences between Arrays and Collections

| Basis                  | Arrays                                                                                               | Collections                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 1. Size                | Fixed after creation.                                                                                | Many collections can grow or shrink dynamically.                                                                              |
| 2. Data types          | Elements must be compatible with the array's declared element type.                                  | Depends on the collection; generic collections specify a type, while non-generic collections can hold different object types. |
| 3. Adding elements     | Cannot increase the array's size directly; a new array is needed.                                    | Many collections provide methods such as `Add()`.                                                                             |
| 4.Removing elements    | Cannot reduce the array's size directly.                                                             | Many collections provide methods such as `Remove()`.                                                                          |
| 5. Built-in operations | Provides basic functionality, with additional operations available through `Array` methods and LINQ. | Often provides convenient methods for adding, removing, searching, and managing elements.                                     |
| 6.Performance          | Can be efficient when the size is fixed and known.                                                   | Depends on the collection type and operation being performed.                                                                 |
| Examples               | `int[]`, `string[]`                                                                                  | `List<T>`, `Dictionary<TKey, TValue>`, `HashSet<T>`, `Queue<T>`                                                               |

# ArrayList 

> 1. `ArrayList` is a non-generic collection in C# 
> 2. that is used to store and manage a group of elements without specifying a particular data type when creating the collection.
> 3. It can store different types of values because it stores elements as `object`.
> 4. Its size can grow or shrink dynamically as elements are added or removed.
> 5. However, it provides less type safety than generic collections and may require explicit type casting when retrieving values.
Therefore, `List<T>` is generally preferred in modern C#.

# List

>1. `List<T>` is a generic collection in C# used to store multiple elements of the **same data type**.
>2. It can dynamically grow or shrink when elements are added or removed.

 ##### Key Points

> 1. Dynamic Size: No need to specify a fixed size; it grows or shrinks automatically.
> 2. Type-Safe: Stores elements of the specified type, such as `int`, `string`, or `double`.
> 3. Index-Based: Elements can be accessed using indexes starting from `0`.
> 4. Built-in Methods: Provides `Add()`, `Remove()`, `Insert()`, `Contains()`, and `Clear()`.
> 5. Count Property: The `Count` property returns the number of elements.

# Array 

> 1. An array in C# is a collection of elements of the same data type 
> 2. stored under a single variable name.
> 3. It has a fixed size, and each element can be accessed using an index starting from `0`

#### Key Points

 >1. Fixed Size: The size of an array is specified when it is created and cannot be changed.
 >2. Same Data Type: An array stores elements of the same type, such as `int`, `string`, or `double`.
 >3. Index-Based: Elements are accessed using indexes starting from `0`.
 >4. `Length` Property: Returns the total number of elements in the array.
 >5. Memory: Arrays store elements in indexed positions, making element access efficient.
 
# Dictionary<TKey, TValue>
 
> 1.  A `Dictionary<TKey, TValue>` in C# is a generic collection that stores data in key-value pairs.
> 2. Each key must be unique, and the key is used to access its corresponding value.
> 3. It belongs to the`System.Collections.Generic` namespace.

#### Key Points

1. Key-Value Pairs: Each element contains a key and its associated value.
2. Unique Keys: Duplicate keys are not allowed.
3. Fast Lookup: Values can be retrieved efficiently using their keys.
4. Type-Safe: `TKey` defines the key's data type, and `TValue` defines the value's data type.
5. Built-in Methods: Provides `Add()`, `Remove()`, `ContainsKey()`, and `TryGetValue()`.

# 1. HashTable

> 1. A Hashtable in C# is a collection that stores data in ==key-value pairs==,
> 2. where each key must be unique.
> 3. It belongs to the `System.Collections` namespace 
> 4. and uses ==hashing to store and retrieve values efficiently.==

#### Key Points

- Key-Value Pairs: Stores each value with an associated key.
    
- Unique Keys: Duplicate keys are not allowed.
    
- Non-Generic: Stores keys and values as `object`, so different data types can be used.
    
- Hashing: Uses a hash code to help locate values efficiently.
    
- Boxing and Unboxing: Value types may require boxing when stored and unboxing when retrieved.

# 2. HashSet
>1. A `HashSet<T>` in C# is a ==generic collection== used to store unique elements of a **specified data type**. 
>2. It belongs to the `System.Collections.Generic` namespace
>3. and automatically prevents duplicate elements.
Key Points
Unique Elements: Does not allow duplicate values.

- Generic Collection: Stores elements of a specified type, such as `int` or `string`.
    
- Fast Lookup: Uses hashing to check whether an element exists efficiently.
    
- No Indexing: Elements cannot be accessed using indexes like `list[0]`.
    
- Built-in Methods: Provides `Add()`, `Remove()`, `Contains()`, and `Clear()`.

# 3.Linear Collections

## Stack

A `Stack<T>` in C# is a generic collection that stores elements using the LIFO (Last In, First Out) principle. This means the last element added to the stack is the first element removed. It belongs to the `System.Collections.Generic` namespace.

## 2. Key Points

- LIFO Principle: The last inserted element is removed first.
    
- `Push()`: Adds an element to the top of the stack.
    
- `Pop()`: Removes and returns the top element.
    
- `Peek()`: Returns the top element without removing it.
    
- `Count`: Returns the total number of elements.
    
- No Indexing: Elements are accessed through stack operations rather than indexes

## Queue

A `Queue<T>` in C# is a generic collection that stores elements using the FIFO (First In, First Out) principle. This means the first element added to the queue is the first element removed. It belongs to the `System.Collections.Generic` namespace.

##### Key Points

- FIFO Principle: The first inserted element is removed first.
    
- `Enqueue()`: Adds an element to the end of the queue.
    
- `Dequeue()`: Removes and returns the element at the front.
    
- `Peek()`: Returns the front element without removing it.
    
- `Count`: Returns the total number of elements.
    
- Generic Collection: Stores elements of a specified type, such as `int` or `string`.

# 4.Collection Interfaces

## `IEnumerable`

`IEnumerable<T>` in C# is an interface that allows you to iterate through a collection of elements one by one. It belongs to the `System.Collections.Generic` namespace and is commonly used with `foreach` to access elements without requiring a specific collection type.

#### Key Points

- Interface: It defines how elements can be iterated over; it is not a collection itself.
    
- Iteration: Supports `foreach` to access elements one by one.
    
- Read-Only Enumeration: It does not provide methods to add, remove, or modify elements in the collection.
    
- Multiple Implementations: Arrays, `List<T>`, and many other collections implement `IEnumerable<T>`.
    
- Deferred Execution: When used with LINQ, query operations may execute only when the results are enumerated.
## `IEnumerator`
`IEnumerator` is an interface in C# that allows us to traverse or iterate through the elements of a collection one element at a time. It provides methods and properties such as `MoveNext()`, `Current`, and `Reset()` to move through a collection and access its elements.

It is commonly used with the `IEnumerable` interface and is the mechanism behind iteration in a `foreach` loop.

#### Simple explanation

Imagine a collection contains five student names. `IEnumerator` lets you move from the first name to the next name, one at a time, until all names have been visited.

Its main members are:

- `MoveNext()` — moves to the next element and returns `true` if an element is available; otherwise, it returns `false`.
    
- `Current` — gets the element at the current position.
    
- `Reset()` — attempts to return the enumerator to its initial position. Support for resetting depends on the enumerator; it may throw `NotSupportedException`.

## `IList`

`IList<T>` is a generic interface in C# that represents a collection of strongly typed elements that can be accessed and managed using an index. It provides operations to add, remove, insert, retrieve, and modify elements at specific positions. It inherits from `ICollection<T>` and `IEnumerable<T>`.

### 2. Simple explanation

- `IList<T>` is used when we need to work with a collection where the position of each element matters.
    
- It allows us to access elements using an index, just like an array.
    
- Indexing starts from `0`.
    
- We can add, insert, update, and remove elements.
    
- `List<T>` is a common class that implements `IList<T>`.

## `ICollection`
`ICollection<T>` is a generic interface in C# that represents a collection of strongly typed elements and provides standard operations to manage them, such as adding, removing, searching, and checking the number of elements. It inherits from `IEnumerable<T>`, so collections implementing `ICollection<T>` can also be iterated through using a `foreach` loop.

### 2. Simple explanation

- `ICollection<T>` defines a common set of operations for working with collections.
    
- The generic type parameter `<T>` specifies the type of elements the collection can contain.
    
- It provides properties and methods such as `Count`, `Add()`, `Remove()`, and `Contains()`.
    
- It extends `IEnumerable<T>`, which means its elements can be traversed one at a time.
    
- Classes such as `List<T>` and `HashSet<T>` implement `ICollection<T>`.
