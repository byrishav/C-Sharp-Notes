# Four Pillars of OOPs

## Encapsulation 

> 1. Encapsulation is one of the Core Principles of Object Oriented Programming.
> 2. It is the practice of wrapping the data and methods that operate on the data into a single unit.
> 3. While restricting direct access to internal data using access modifiers.

## Abstraction

>1. Abstraction is an OOP concept that hides the implementation details.
>2. and exposes only the essential features to the user.
>3. It focuses on what the object does rather than how it does it.

## Inheritance

> 1. Inheritance is an OOP principle in which one class ==acquires accessible members and behavior== from another class.
> 2. allowing code reuse and the creation of relationships between classes.
> 3. In C#, the class being inherited from is called the base class (parent), and the class that inherits from it is called the derived class (child).

## Polymorphism

>1. Polymorphism is an OOP principle that allows
>2. the ==`same method name, interface, or base-class reference`== to represent different behaviors 
>3. depending on which object uses it or how is it called.
>4. The word polymorphism means many forms. 

# Keywords

## this Keywords

> 1. The `this` keyword in C# refers to the current object that is being used of a class.
> 2. It is used to access the current object's fields, properties, and methods
> 3. especially when a local variable or method parameter has the same name as a class field.

## base Keyword

>The `base` keyword in C# is used inside a derived class to access members of its base (parent) class, such as constructors, methods, and properties.

In simple words, `base` means the parent class part of the current object.

## static Keyword

>1. The `static` keyword in C# is used to declare a member that belongs to the class itself 
>2. rather than to a particular object (instance) of that class.

In simple words, a static member belongs to the class, so you generally access it using the class name without creating an object.

# Classes and Objects

## Class Definition 

>1. A class in C# is a blueprint or template for creating objects.
>2. It ==defines the data an object can contain== through fields and properties,
>3. and ==the actions it can perform== through methods.
>4. In simple words, a class describes what an object will have and what it can do.

## Object Definition

> 1. An object in C# is an instance of a class
> 2. that represents an entity(a real world thing)
> 3. stores data 
> 4. and performs actions defined by the class.

# Abstract class and methods 

## Abstract Class

> 1. An abstract class is a class whose object cannot be created directly.
> 2. It is used as a base class for other classes and can contain both normal methods (with code) and abstract methods (without code).

## Abstract Method

>1. An abstract method is a method that has no code in the abstract class, 
>2. and its derived class must provide the code for it.

# Interface

>1. An interface in C# defines a set of methods and properties that a class must implement.
>2. It tells a class what it must do, but not how to do it.

## Abstract Class vs Interface in C#

|Abstract Class|Interface|
|---|---|
|Can contain methods with and without code.|Defines members a class must implement; modern C# also supports default implementations.|
|A class can inherit from only one base class.|A class can implement multiple interfaces.|
|Uses the `abstract class` keyword.|Uses the `interface` keyword.|
# Types of inheritance 

>C# inheritance is commonly classified into single, multilevel, hierarchical, multiple, and hybrid inheritance. However, C# does not support multiple inheritance through classes, but a class can implement multiple interfaces

### Single Inheritance
>Single inheritance is a type of inheritance in which one child class inherits from one parent class.

### Multilevel Inheritance
>Multilevel inheritance is a type of inheritance in which a class inherits from another class, and a third class inherits from that derived class

### Hierarchical Inheritance
>Hierarchical inheritance is a type of inheritance in which multiple child classes inherit from the same parent class.

### Multiple Inheritance
>1. Multiple inheritance is a type of inheritance in which one child class inherits from more than one parent class.
>
>2. C# does not support multiple inheritance through classes, but it supports implementing multiple interfaces
>   

### Hybrid Inheritance

>1. Hybrid inheritance is a combination of two or more types of inheritance in a single program.
>2. It helps combine different inheritance structures to reuse code.
>3. C# does not support multiple inheritance through classes, but hybrid structures can be created using classes and interfaces.

# Polymorphism

## Compile Time Polymorphism 

> 1. Compile-time polymorphism allows the same method name to perform different tasks based on the parameters passed.
> 2. It is mainly achieved through method overloading.
> 3. Methods must have different parameter lists, such as different numbers or types of parameters.
> 4. The compiler decides which method to call during compilation.

## Runtime Polymorphism

> 1. Runtime polymorphism allows the same method to perform different actions ==depending on which object calls it==.
> 2. It is commonly achieved through method overriding using `virtual` and `override` keywords.
> 3. The method that runs is decided at runtime based on the actual object.
> 4. It allows different classes to provide their own implementation of the same method.

## new Keyword

> 1. The `new` keyword is used to create an object of a class.
> 2. It allocates memory for the object and calls its constructor.
> 3. It can also be used to hide a member inherited from a parent class.

## Method Overloading 

 >1. Method overloading means creating multiple methods with the same name but different parameters in the same class.
 >2. Parameters can differ in number, type, or order.
 >3. It is a form of compile-time polymorphism.

## Method Overriding 

> 1. Method overriding means a child class provides its own implementation of a method already defined in the parent class.
> 2. The method in the parent class must be marked `virtual` or `abstract`, and the child class uses `override`.
> 3. It is a form of runtime polymorphism.
