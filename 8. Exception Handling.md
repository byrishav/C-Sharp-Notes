## Errors

> 1. Errors are problems in a program that can prevent it from compiling or running correctly.
> 2. They can occur due to incorrect syntax, invalid operations, or problems during execution.
> 3. Errors are commonly classified as compile-time errors and runtime errors.

## Exceptions

> 1. An exception is a problem that occurs while a program is running and interrupts its normal execution.
> 2. Exceptions can occur when dividing by zero, accessing a file that doesn't exist, or connecting to an unavailable database.
> 3. C# provides `try` and `catch` blocks to handle exceptions and keep the program from stopping unexpectedly.
> 4. The `finally` block is used to run cleanup code, whether an exception occurs or not.
> 5. Common exceptions include `DivideByZeroException`, `NullReferenceException`, and `FileNotFoundException`.

# Exception Types 

## 1. `NullReferenceException`

- Ye tab hoti hai jab hum `null` reference ke through kisi object ka member access karte hain.
    
- Matlab, object available nahi hai, lekin hum uska data ya method use karne ki koshish karte hain.
    
- Isse bachne ke liye object ko initialize karo ya null check lagao.
    

```
string? name = null;
Console.WriteLine(name.Length); // NullReferenceException
```

## 2. `DivideByZeroException`

- Ye tab hoti hai jab hum kisi integer ya decimal number ko zero se divide karte hain.
    
- Zero se integer division valid nahi hota.
    
- Division se pehle denominator check kar sakte hain.
    

```
int a = 10;
int b = 0;
Console.WriteLine(a / b); // DivideByZeroException
```

## 3. `IndexOutOfRangeException`

- Ye tab hoti hai jab hum array ko uski valid index range ke bahar access karte hain.
    
- Array ki indexing `0` se start hoti hai.
    
- Access karne se pehle index ko valid range mein check karna chahiye.
    

```
int[] numbers = { 10, 20, 30 };
Console.WriteLine(numbers[5]); // IndexOutOfRangeException
```

## 4. `ArgumentException`

- Ye tab hoti hai jab kisi method ko invalid argument diya jata hai.
    
- Argument ka type sahi ho sakta hai, lekin uski value acceptable nahi hoti.
    
- Method call karne se pehle input values validate karni chahiye.
    

```
// Example: A method rejects an invalid argument.
throw new ArgumentException("Invalid argument");
```

## 5. `ArgumentNullException`

- Ye `ArgumentException` ka specialized type hai.
    
- Ye tab hoti hai jab kisi method ko aisa argument diya jata hai jo `null` nahi hona chahiye.
    
- Required input ke null hone par validation ke liye use ki ja sakti hai.
    

```
string name = null!;
ArgumentNullException.ThrowIfNull(name);
```

## 6. `FormatException`

- Ye tab hoti hai jab kisi value ko expected format mein convert nahi kar sakte.
    
- Example: `"abc"` ko integer mein convert karna.
    
- `int.TryParse()` use karke invalid input ko safely handle kar sakte hain.
    

```
int number = int.Parse("abc"); // FormatException
```

## 7. `OverflowException`

- Ye tab hoti hai jab calculation ka result kisi data type ki allowed range se bahar chala jata hai, in a checked context.
    
- Example: `int` ki maximum value se bada result store karne ki koshish.
    
- Isse bachne ke liye values aur calculations ki range check karo.
    

```
int n = int.MaxValue;
checked
{
    n = n + 1; // OverflowException
}
```

## 8. `InvalidOperationException`

- Ye tab hoti hai jab koi operation current situation mein allowed nahi hota.
    
- Object exist kar sakta hai, lekin us waqt operation perform nahi kar sakta.
    
- Operation se pehle object ki current state check karni chahiye.
    

```
var numbers = new List<int>();
Console.WriteLine(numbers.First()); // InvalidOperationException
```

## 9. `InvalidCastException`

- Ye tab hoti hai jab kisi object ko incompatible type mein cast karne ki koshish hoti hai.
    
- Har type ko doosre type mein directly convert nahi kar sakte.
    
- `is`, pattern matching, ya suitable conversion methods se type check kar sakte hain.
    

```
object value = "Hello";
int number = (int)value; // InvalidCastException
```

## 10. `IndexOutOfRangeException` vs `KeyNotFoundException`

`KeyNotFoundException` ko alag se yaad rakho:

- Ye tab hoti hai jab dictionary mein aisi key search karte hain jo exist nahi karti.
    
- Dictionary key-value pairs store karti hai.
    
- `TryGetValue()` use karke missing key ko safely handle kar sakte hain.
    

```
var ages = new Dictionary<string, int>();
Console.WriteLine(ages["Rishav"]); // KeyNotFoundException
```

## 11. `IOException`

- Ye file ya input/output operations se related problems ke liye use hoti hai.
    
- Example: file read ya write karte waqt I/O problem hona.
    
- `try-catch` ka use karke error handle kar sakte hain.
    

```
// IOException can occur during file operations.
File.ReadAllText("data.txt");
```

## 12. `FileNotFoundException`

- Ye `IOException` ka derived type hai.
    
- Ye tab hoti hai jab jis file ko open ya read karna hai, woh nahi milti.
    
- File ka path aur existence check karna chahiye.
    

```
File.ReadAllText("missing.txt"); // FileNotFoundException
```

## 13. `UnauthorizedAccessException`

- Ye tab hoti hai jab program ke paas kisi file, folder, ya resource ko access karne ki permission nahi hoti.
    
- Example: restricted file ko read karne ki koshish.
    
- File permissions aur application access check karna chahiye.
    

## 14. `TimeoutException`

- Ye tab hoti hai jab koi operation allowed time ke andar complete nahi hota.
    
- Example: kisi operation ka response aane mein bahut zyada time lagna.
    
- Timeout settings, retry logic, aur error handling use ki ja sakti hai.
    

## 15. `OutOfMemoryException`

- Ye tab hoti hai jab program ko required memory allocate nahi ho pati.
    
- Bahut zyada memory use karna iska ek possible reason hai.
    
- Unnecessary objects aur memory usage ko reduce karna chahiye.
    

## 16. `StackOverflowException`

- Ye tab hoti hai jab call stack ki capacity exceed ho jati hai, often because of excessive recursion.
    
- Example: koi method bina stopping condition ke khud ko baar-baar call kare.
    
- Recursion ki stopping condition sahi rakho. Is exception ko normal `try-catch` se reliably recover nahi kar sakte.
    

## 17. Custom Exception

- Custom exception woh exception hai jo developer apni application ki specific problem ke liye banata hai.
    
- Iske liye aam taur par `Exception` class se inherit karte hain.
    
- Ye business rules ko clearly represent karne mein useful hai, jaise insufficient account balance.


# Exception Handling Statements

## try block

>1. The `try` block contains code that may cause an exception while the program is running.
>2. If an exception occurs, C# looks for a matching `catch` block to handle it.
>3. The `try` block must be followed by at least one `catch` or `finally` block.

## catch block

>1. The `catch` block is used to handle exceptions that occur in the `try` block.
>2. It allows the program to respond to an error instead of stopping unexpectedly.
>3. We can use different `catch` blocks to handle different types of exceptions.

## multiple catch block 

>1. Multiple `catch` blocks allow us to handle different types of exceptions separately.
>2. Each `catch` block handles a specific type of exception, such as `FormatException` or `DivideByZeroException`.
>3. When an exception occurs, C# executes the first matching `catch` block.
>4. Specific exception types should come before general exception types like `Exception`.

## finally

>1. The `finally` block contains code that runs whether an exception occurs or not, provided control exits the `try` statement normally through its exception-handling flow.
>2. It is mainly used for cleanup tasks, such as closing files or releasing resources.
>3. It usually executes after the `try` and `catch` blocks.

## `throw` vs `throw ex`

>1. `throw`: Rethrows the current exception and preserves its original stack trace.
>2. `throw ex`: Throws the exception again but resets the stack trace to the current location, making the original error location harder to identify.
>3. Best practice: Use `throw;` when rethrowing an exception inside a `catch` block.

## Exception Propagation

>1. Exception propagation is the process
>2. in which an exception moves up the method call stack 
>3. until it is handled by a matching `catch` block.
>4. If no matching handler is found, the program may terminate.
